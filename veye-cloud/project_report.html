接口清单

  • GET /health：健康检查（返回 vLLM base_url、当前 model）
  • POST /vision/identify：图片识别（multipart form）
  • POST /sos：SOS/事件上报（JSON body）
scene 枚举：toxic_plant / medicine / generic（其它值会返回 422）

启动方式（常用命令）

在服务器上执行（默认在 /root/veye-cloud）：
# 1) 启动 vLLM（常规脚本）
cd /root/veye-cloud
source .venv/bin/activate
./scripts/start_vllm.sh

# 2) vLLM 若因显存/缓存不稳定，可用“保守参数”启动脚本
./scripts/run_vllm_direct.sh

# 3) 启动 API
./scripts/start_api.sh

# 4) 快速自检
curl -sS http://127.0.0.1:8001/v1/models | head
curl -sS http://127.0.0.1:6006/health

本次关键修复点（从问题到结果）

  • 模型获取：服务器无法访问 HuggingFace → 使用 ModelScope 下载到 /root/autodl-tmp，避免根盘空间不足。
  • vLLM 参数兼容：--limit-mm-per-prompt 需要 JSON 字符串（如 {"image": 1}）。
  • vLLM 启动 OOM：启动阶段显存不足/引擎 warmup OOM → 调参（降低 max-model-len、max-num-seqs、启用 --enforce-eager、调整 gpu-memory-utilization）后成功启动。
  • 鉴权：API Key 设为可选（为空则不鉴权）。
  • 数据库可用性：DB 不可用时服务允许启动；需要落库的接口会返回 503 database_unavailable。
  • 端到端验证：/vision/identify 已返回结构化 JSON（含 label_main、risk_level、summary、latency_ms）。

当前 vLLM 运行参数（为稳定启动而偏保守）

--host 127.0.0.1
--port 8001
--dtype bfloat16
--enforce-eager
--gpu-memory-utilization 0.80
--max-model-len 1024
--max-num-seqs 1
--limit-mm-per-prompt {"image": 1}
